# Commerce evidence access contract

When connected to a recommender experiment, use the supplied commerce evidence to examine relevant alternatives and compare supported capabilities. The trusted harness fixes your provider or allowed record IDs; query requests cannot enlarge that scope. Only use buyer preferences revealed under the game's information policy. The graph itself contains no private buyer brief or numerical satisfaction function.

A reported capability is a source-supported claim, not independent product validation. Unknown is different from explicit negative evidence. Qualified claims retain unresolved scope or copy issues; manual and automatic functions need not contradict each other. Candidate identity links are not established product equivalence. A product reference is scoped to one offer unless an accepted identity decision says otherwise.

Use frozen offer prices for budget arithmetic. Later landing-page seller and price observations are not exposed by this access contract. Storefront labels do not establish the actual seller or enforceable recourse. Capability coverage alone does not establish component compatibility or a complete purchase.

The query interface can find offers with reported capabilities, inspect scoped evidence, compare explicit offers, and summarize proposed bundle coverage and frozen cost. Retrieval order is deterministic, not a satisfaction or revenue recommendation. Continue to follow the surrounding game's objectives and response schema. Returned cards must remain the original card objects; communicate relevant evidence through the permitted message channel.

This file defines a future agent integration contract. The accompanying offline access audit executes fixed example queries, not language-model turns, recommendations or purchases.
